● Read all 7 files. Notable observations:

  Architecture: Single-provider NVIDIA proxy. FastAPI app on 127.0.0.1:8788,
  speaks both OpenAI (/v1/chat/completions) and Anthropic (/v1/messages) wire
  shapes, routes everything to NVIDIA's GLM-5.2 endpoint.

  Key files:
  - atlas_proxy.py (1278 lines) — main app, handlers, failover loop, SSE
  adapters, stats endpoints
  - nvidia_key_store.py — sticky key pool with per-key cooldown, mtime-reload
  from keys.txt
  - nvidia_client.py — httpx wrapper with split timeouts (flat for non-stream,
  generous read for stream)
  - openai_compat.py (2469 lines) — payload sanitization, Anthropic↔OpenAI
  conversion, full Responses API port
  - system_prompt.py — strips <system-reminder> blocks, rewrites Claude-identity
  leakage, injects end-of-conversation reinforcement
  - stats.py / token_tracker.py — since-restart + all-time counters, persisted
  to data/proxy_stats.json

  Things worth flagging:

  1. openai_compat.py has duplicate code. The
  ResponsesInput/ResponsesRequest/ResponsesStreamConverter classes are defined
  twice (lines ~17-543 and again ~1530-2467). The second copy is a slightly
  extended version (adds include/conversation fields, different ResponsesRequest
  signature). Dead code or active — unclear without checking imports.
  2. nvidia_client.py:130-149 has a docstring inside a method body. The """Open 
  a streaming chat request...""" block sits between executable statements, not
  as the function's docstring. Python tolerates it (it's a string literal
  expression, evaluated and discarded) but it's ugly and confusing.
  3. system_prompt.py is the override machinery. It mutates the body to strip
  Claude identity ("I'm Claude" → "I'm Atlas") and injects a compact reminder
  before the final user turn. This is the adherence layer — without it, GLM-5.2
  falls back to safety training on multi-turn requests.
  4. atlas_proxy.py has a known dead-code path. handle_non_stream records
  record_failure on terminal errors but the streaming path's wrap_error
  callbacks don't always record failures — stream_error and
  _anthropic_stream_error are pure response builders. Failures are recorded in
  _stream_failover_loop directly, so it works, but the separation is fragile.
  5. MAX_BODY_BYTES = 256 MiB — explicitly raised from 2 MiB to fix the
  "Internal Error at ~135k context" bug. Comment explains why.
  6. No /v1/responses endpoint in atlas_proxy.py. The Responses API conversion
  code exists in openai_compat.py but nothing routes to it. Either dead code or
  wired up elsewhere.
